# Блок 1. Закупки и работа с поставщиками

## Кейс 1.1. Автоматическое заполнение реквизитов документа «Заказ поставщику»

**Задача:** Автоматизировать заполнение ключевых реквизитов документа «Заказ поставщику» для ускорения работы отдела закупок.

**Что сделано:**

- Реализовано автозаполнение реквизита «Склад» значением «Центр» (группа складов) при создании документа.
- Настроено автоматическое заполнение реквизита «РегистрироватьЦеныПоставщика» значением «Истина».
- Реализовано заполнение реквизита «ЦенаВключаетНДС» значением «Истина».
- При заполнении/изменении в ТЧ «Товары» реквизита «Номенклатура» автоматически заполняется:
  - реквизит «Склад» ТЧ «Товары» значением `Номенклатура.ДополнительныеРеквизиты.Склад`;
  - реквизит «ВидЦеныПоставщика» ТЧ «Товары» значением «Закупочная» (справочник «ВидыЦенПоставщиков» по владельцу `ЗаказПоставщику.Партнер`).

**Необходимые условия:**

1. В 1С:ERP включена функциональная опция «Закупки — Документы закупок — Поступление товаров на несколько складов».
2. Все физические склады включены в иерархию группы складов «Центр» с реквизитом `ВыборГруппы = РазрешитьВЗаказахИНакладных`.
3. Для справочника «Номенклатура» определён общий дополнительный реквизит «Склад» (тип — `Справочники.Склады`).

**Результат:** Ускорение создания заказов поставщику за счёт автоматического заполнения критичных реквизитов.

## Кейс 1.2. Автоматический контроль заполнения цен

**Задача:** Исключить ошибки при установке цен ниже зарегистрированных цен поставщика.

**Что сделано:**

- При интерактивном или программном проведении документа «Установка цен номенклатуры» реализовано сравнение введённой цены с последней зарегистрированной ценой поставщика (срез последних на дату документа для регистра сведений «Цены номенклатуры поставщиков»).
- Если `ВидыЦен.ВалютаЦены > "руб."`, сравнение выполняется в рублёвом эквиваленте (срез последних по регистру сведений «Курсы валют»).
- Если введённая цена меньше цены поставщика, выводится сообщение:
  > «Для строки [НомерСтроки] цена для вида цен [ВидЦены]=[Цена] [ВалютаЦены] меньше цены последней закупки [ЦенаЗакупки]руб.»
- Реализация относится к видам цен со способом задания цены «Произвольный запрос к ИБ».

**Результат:** Контроль цен на этапе установки, предотвращение убыточных продаж.

## Кейс 1.3. Разработка отчёта по состояниям выполнения «Заказов поставщику»

**Задача:** Создать АРМ для менеджеров отдела закупок на основе типового отчёта «Состояние выполнения документов».

**Что сделано:**

- Разработан отчёт с группировками:
  - «Заказ поставщику» (с наименованием поставщика и суммой документа);
  - «Номенклатура»;
  - «Документы» (Приобретение товаров и услуг, Приходный ордер на товары).
- Добавлены колонки: «Склад» (после Номенклатуры), «Комментарий» (для группировки «Документы»).
- Реализована расшифровка по группировкам.
- Настроены отборы: по дате, по реквизитам документа, по состоянию («В работе», «Все», «Отработанные»).
- Колонка «Принимается» переименована в «Принимается (БРАК)» с нежно-розовой подсветкой.
- Добавлена колонка «Недовоз» с нежно-зелёной подсветкой (значение = «К поступлению» − «Принимается» − «Принято»).
- Команда запуска вынесена в меню «Отчёты» — «АРМ Состояние выполнения заказов».
- Реализовано сохранение и восстановление настроек отборов.
- Строки по номенклатуре, поступившей на склад брака, выделяются нежно-розовым цветом.

**Результат:** Удобный инструмент контроля исполнения заказов поставщикам для менеджеров ОЗ.

## Кейс 1.5. Автоматическое заведение цен

**Задача:** Автоматически создавать и проводить документ «Установка цен номенклатуры» на основании «Заказа поставщику».

**Что сделано:**

- После проведения «Заказа поставщику» проверяется наличие введённого на его основании документа «Установка цен номенклатуры».
- Если документ отсутствует — создаётся; если найден — отменяется проведение, очищается и перезаполняется.
- Заполнение типовое (виды цен с реквизитом «При вводе на основании документов поставки» = Истина).
- После заполнения документ автоматически проводится.
- Сравнивается новая цена «Закупочная (цена поступления)» с последней зафиксированной ненулевой ценой из регистра сведений «Цены номенклатуры». При превышении выводится сообщение:
  > «Внимание! Закупочная цена для артикула номенклатуры [Артикул] ([Наименование]) увеличилась с [Старая цена] на [Новая цена]»
- При отмене проведения «Заказа поставщику» отменяется проведение связанного «Установка цен номенклатуры».

**Результат:** Автоматическая фиксация закупочных цен с контролем роста.

## Кейс 1.6. Автоматическое заполнение табличной части документа «Заказ поставщику»

**Задача:** Реализовать кнопку «Разбить строки по браку» на форме документа «Заказ поставщику».

**Что сделано:**

- Реализована выгрузка ТЧ «Товары» в таблицу значений.
- Для строк со складом «Склад №2/1 (Брак заводской)» или «Склад №2/2 (Брак-транспортный)» устанавливается склад из `Номенклатура.ДопРеквизиты.НоменклатураСклад`.
- Таблица сворачивается по ключевым полям с суммированием количества и суммы.
- Анализируются приходы по регистру «Товары к поступлению» по измерениям: документ поступления, номенклатура, склад.
- При обнаружении приходов создаётся копия строки с количеством = мин(количество, принимается) и складом брака, пересчитывается сумма и цена.
- Строки с браком выделяются нежно-розовым цветом.

**Результат:** Корректное разделение строк заказа по складам брака.

## Кейс 1.7. Автоматическое заведение номенклатуры поставщиков

**Задача:** Автоматически создавать элементы справочника «Номенклатура поставщиков» при записи номенклатуры.

**Что сделано:**

- При записи элемента справочника «Номенклатура» выполняется поиск в справочнике «Номенклатура поставщиков» по полям: владелец, номенклатура, артикул (и доп. реквизиты).
- Если для всех заполненных доп. реквизитов элемент найден — ничего не делается.
- Для каждого ненайденного доп. реквизита создаётся элемент справочника «Номенклатура поставщиков» с заполнением владельца, номенклатуры, артикула и наименования.

**Результат:** Автоматическое ведение номенклатуры поставщиков.

## Кейс 1.8. Доработка документа «Приходный ордер на товары»

## Кейс 1.9. Доработка документа «Установка цен номенклатуры»

**Задача:** Доработать документ «Установка цен номенклатуры».

**Что сделано:**

- При записи документа (программной или интерактивной) проверяется реквизит «ДокументОснование». Если он НЕ заполнен:
  - проверяется наличие в ТЧ «ВидыЦен» служебных видов цен (`УстанавливатьЦенУПриВводеНаОсновании = Истина`); если найдены — удаляются из ТЧ с выводом сообщения:
    > «Ввод служебной цены [ВидЦены] разрешен только на основании документов поступления»;
  - проверяется наличие в ТЧ «Товары» служебных видов цен; если найдены — удаляются из ТЧ;
  - если в ТЧ «Товары» не осталось строк — документ записывается только непроведённым.

**Результат:** Контроль корректности заполнения документа «Установка цен номенклатуры».

## Кейс 1.10. Обработка непринятых позиций в «Заказе поставщику»

**Задача:** Доработать обработку «Помощник закрытия заказов» для работы с непринятыми позициями.

**Что сделано:**

- На странице «СтраницаНачальная» выведен чекбокс (по умолчанию ЛОЖЬ) и поле ввода «Дата поступления» (по умолчанию — текущая дата).
- Доступность поля «Дата поступления» зависит от состояния чекбокса.
- После выполнения типового обработчика команды «Готово»:
  - если чекбокс ИСТИНА: создаётся новый документ «Заказ поставщику» копированием текущего, заполняется «Дата поступления», копируются только строки с `Отменено = ИСТИНА` (с последующей установкой `Отменено = ЛОЖЬ`), выполняется привязка документа 1С:ТиС;
  - если чекбокс ЛОЖЬ: удаляются отменённые строки из документа 1С:ТиС «Приходная накладная» с отменой привязки к документам «Заявка ОП для ОЗ» и «Заявка производства для ОЗ».

**Результат:** Корректная обработка непринятых позиций.

# Блок 2. Логистика и доставка

## Кейс 2.1. Доработка АРМ «Доставка»

**Задача:** Доработать типовой АРМ «Доставка» для группировки распоряжений по партнёру и корректного вывода веса/объёма.

**Что сделано:**

- Реализована группировка распоряжений на доставку по полю `ПолучательОтправитель` с возможностью включения/выключения через команду «Включить/выключить группировку по Партнеру».
- Изменён алгоритм вывода веса и объёма: данные берутся не по номенклатуре, а по распоряжению (документ «Заказ поставщику») в целом из доп. реквизитов «Вес заказа» и «Объем заказа».
- Если доп. реквизиты не заполнены — выводится значение «не указан».
- При добавлении строки в ТЧ «Распоряжения» документа «Задание на перевозку» реквизиты «Вес» и «Объем» заполняются из доп. реквизитов «Заказ поставщику».

**Необходимые условия:** Для документа «Заказ поставщику» определены доп. реквизиты «Вес заказа» (Ч15,3) и «Объем заказа» (Ч15,3).

**Результат:** Удобная работа логистов с распоряжениями, точный расчёт загрузки транспорта.

- В колонке «Объём» добавлено отражение границ ячеек.

**Результат:** Печатная форма соответствует реальному процессу доставки.

## Кейс 2.3. Разработка ПФ «Заявка на перевозку» документа «Задание на перевозку»

## Кейс 2.4. Доработка АРМ «Доставка» (2)

**Задача:** Доработать АРМ «Доставка» для совместной работы с распоряжениями на доставку на склад и со склада.

- Реализован расчёт веса и объёма с учётом упаковок: если упаковки есть — вес и объём берутся из подходящей упаковки; если остаток не помещается — по данным карточки номенклатуры.

**Результат:** Корректный расчёт загрузки транспорта для разных типов распоряжений.

## Кейс 2.5. Доработка документа «Задание на перевозку»

**Задача:** Доработать документ «Задание на перевозку» для работы с перевозчиками.

**Что сделано:**

- Реквизит «Перевозчик» доступен на форме документа независимо от вида перевозок.

- При изменении перевозчика автоматически заполняются реквизиты «Водитель» и «Транспортное средство» по соответствию перевозчику.
- При выборе водителя и транспортного средства устанавливаются отборы по перевозчику.
- При создании документа всегда устанавливается реквизит «Операция» = «СоСклада».

**Результат:** Корректная работа с перевозчиками в заданиях на перевозку.

## Кейс 2.6. Автоматизация формирования доверенностей

**Задача:** Автоматизировать формирование доверенностей на основании документа «Задание на перевозку».

- На форму документа «Задание на перевозку» добавлена кнопка «Сформировать доверенности».

- Перед созданием проверяется наличие уже созданных документов «Доверенность»; актуальные перезаполняются, неактуальные помечаются на удаление.
- После формирования документов автоматически отправляется уведомление ответственным пользователям (менеджерам по заказам поставщику) с текстом:
  > «Сформирована доверенность на получение товаров от поставщика [Поставщик]»
- Доработана типовая ПФ М-2: добавлены марка и номер автомобиля, марка и номер прицепа.

**Результат:** Автоматизация формирования доверенностей.

## Кейс 3.1. Доработка документа «Коммерческое предложение»

**Задача:** Доработать документ «Коммерческое предложение» для управления способом доставки и формирования счетов.

**Что сделано:**

- Отключена видимость и необходимость заполнения реквизита «Организация».
- В ТЧ «Товары» добавлен реквизит «Способ доставки» (перечисление: Самовывоз, Планировать доставку).
- При добавлении новой строки значение автоматически устанавливается в «Самовывоз».
- Добавлены кнопки «Заполнить способ доставки (Самовывоз)» и «Заполнить способ доставки (Планировать доставку)».
- Добавлена кнопка «Сформировать счета» на форму документа и списка, при нажатии формируются документы «Заказ клиента» с группировкой по:
  - организации-продавцу (определяется по алгоритму с учётом бизнес-региона, налогообложения, товарной группы);
  - наличию товаров на складах;
  - способу доставки.
- Реализовано заполнение реквизитов «Заказ клиента»: организация, договор, склад, способ доставки, вариант обеспечения, склад.
- Созданные документы проводятся и отражаются в отчёте «Связанные документы».

**Результат:** Автоматическое формирование заказов клиента на основании коммерческого предложения.

**Что сделано:** Реализована обработка, запускаемая как регламентное задание, которая обновляет курсы валют (EUR и USD) с добавлением 2% к актуальному значению в:

- справочнике «Валюты» 1С:ТиС;
- файле `\\server\Товары_Прайсы_Информация\ИНФОРМАЦИЯ ПО ТОВАРУ\КУРС ВАЛЮТ.xls`.

**Результат:** Автоматическое обновление курсов валют.

## Кейс 6.3. Доработка документа «Эквайринговая операция»

**Задача:** Доработать документ «Эквайринговая операция».

**Что сделано:**

- Реквизит «Номер платежной карты» сделан необязательным для ввода.
- Перед записью документа проверяется заполнение этого реквизита; если не заполнен — заполняется строковым значением «0».

**Результат:** Упрощение ввода эквайринговых операций.

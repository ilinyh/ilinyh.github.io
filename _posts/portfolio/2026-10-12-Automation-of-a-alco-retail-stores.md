## Кейс 1. Генерация промокодов с контрольной суммой

**Задача**

Для проведения маркетинговой акции требовалось сгенерировать уникальные промокоды для покупателей, которые применялись бы при пробитии чеков. Код должен содержать информацию о префиксе чека, категории акции и контрольную сумму для проверки подлинности. Также была необходимость настраивать порог суммы срабатывания акции.

**Что сделано**

Разработан алгоритм генерации 15-символьного промокода, включающего зашифрованный префикс чека, категорию акции и контрольную сумму, с исключением неоднозначных символов (буква «O»). Реализована проверка уникальности сгенерированного кода через регистр сведений «Акция10лет» с повторной генерацией при коллизии. Введён параметр «Сумма срабатывания акции», позволяющий гибко настраивать минимальную сумму чека для участия в акции.

```bsl
Результат = Сред(Мусор,  Гсч.СлучайноеЧисло(1, СтрДлина(Мусор)), 1) + ЗашПреф4 + ЗашКат2 
  + Сред(Мусор,  Гсч.СлучайноеЧисло(1, СтрДлина(Мусор)), 1) + КонтрЧисло2 + ЗашКат1 + Сред(Мусор,  Гсч.СлучайноеЧисло(1, СтрДлина(Мусор)), 1)
	+ КонтрЧисло3 + ЗашПреф2 + ГенерируемБуквы(ИсключаемыйСимвол) + Сред(Мусор,  Гсч.СлучайноеЧисло(1, СтрДлина(Мусор)), 1)
	+ ЗашПреф1 + КонтрЧисло1 + ЗашПреф3 + Сред(Мусор,  Гсч.СлучайноеЧисло(1, СтрДлина(Мусор)), 1);
	
Запрос = Новый Запрос;
Запрос.Текст = "ВЫБРАТЬ
               |	Акция10лет.Склад,
               |	Акция10лет.ЧекККМ,
               |	Акция10лет.КодАкции
               |ИЗ
               |	РегистрСведений.Акция10лет КАК Акция10лет
               |ГДЕ
               |	Акция10лет.КодАкции = &КодАкции";
Запрос.УстановитьПараметр("КодАкции", Результат);
РезультатЗапроса = Запрос.Выполнить();
Если НЕ РезультатЗапроса.Пустой() Тогда
  Результат = ГенерироватьКодАкции(ТекЧек, СуммаСрабатыванияАкции);
КонецЕсли;	
Возврат Результат;
```

**Результат**

Маркетинговая акция проведена: покупатели получают промокоды в чеках, система гарантирует их уникальность, порог срабатывания настраивается без изменения кода. Механизм шифрования префикса и контрольной суммы обеспечивает защиту от подделки кодов.

## Кейс 2. Акции «Подарки при покупке» и «Основная-подчиненная номенклатура»

**Задача**

Требовалось реализовать два типа акций: «Однократная акция» (подарок при покупке конкретного товара, применяется один раз за чек) и «Основная-подчиненная номенклатура» (скидка на подчиненный товар при покупке основного в указанном количестве). Акции должны автоматически применяться в табличной части документов продажи.

**Что сделано**

Разработан механизм применения акций в табличной части документов через общий модуль «Обработка табличных частей». Для однократных акций реализован поиск в регистре сведений «Подарки при покупке» с фильтрацией по территории, датам действия и признаку «Однократно». Для акции «основная-подчиненная номенклатура» разработан алгоритм сопоставления строк табличной части через запрос с внутренними соединениями и группировкой по номенклатуре. Реализовано заполнение реквизитов при проведении документа «Установка акции товары по сниженной цене»: однократность, количества основной и подчиненной номенклатуры, процент скидки, цены. Добавлена валидация обязательных полей в табличной части. В документе «Чек ККМ» реализован пропуск проверки заполнения реквизитов для товаров, участвующих в однократных акциях.

## Кейс 3. Загрузка заказов поставщикам из XML

**Задача**

Поставщики присылали заказы в виде XML-файлов, которые требовалось автоматически загружать в систему для создания приходных ордеров. Необходимо было обеспечить корректную обработку как одиночных, так и множественных сообщений в одном файле.

**Что сделано**

Доработан обработчик «Загрузка ПО»: реализовано чтение XDTO-объектов из XML-файла с определением типа сообщения. Добавлен обработчик массива заказов с фильтрацией по непустому GUID. Реализован контроль наличия данных для загрузки с уведомлением пользователя при пустом файле.

```bsl
Функция СоздатьПриходныйОрдерПоЗаказу(Файл) Экспорт
	
	СписокГУИД = Новый СписокЗначений;
	
	ЧитатьХМЛ = Новый ЧтениеXML;
	Попытка
		ЧитатьХМЛ.ОткрытьФайл(Файл.ПолноеИмя);
		Фабрика = ФабрикаXDTO.ПрочитатьXML(ЧитатьХМЛ);
	Исключение
		ЧитатьХМЛ.Закрыть();
		ВызватьИсключение "Не удалось прочитать файл """ + Файл.ПолноеИмя + """: " 
			+ ОписаниеОшибки();
	КонецПопытки;
	
	Сообщение = Фабрика.Message;
	Если Сообщение = Неопределено Тогда
		Сообщить("Не обнаружено данных для загрузки!");
		Возврат СписокГУИД;
	КонецЕсли;
	
	// Приводим к коллекции для единообразной обработки.
	// Используем ТипЗнч вместо отсутствующего ЭтоОбъектXDTO
	Если ТипЗнч(Сообщение) = Тип("ОбъектXDTO") Тогда
		КоллекцияЗаказов = Новый Массив;
		КоллекцияЗаказов.Добавить(Сообщение);
	Иначе
		КоллекцияЗаказов = Сообщение; // это СписокXDTO
	КонецЕсли;
	
	Для Каждого Заказ Из КоллекцияЗаказов Цикл
		Если ТипЗнч(Заказ) <> Тип("ОбъектXDTO") Тогда
			Продолжить;
		КонецЕсли;
		ГУИД = ПолучитьГУИДЗаказа(Заказ);
		Если ПустаяСтрока(ГУИД) Тогда
			Продолжить;
		КонецЕсли;
		СоздатьПО(Заказ, СписокГУИД);
	КонецЦикла;
	
	Если СписокГУИД.Количество() = 0 Тогда
		Сообщить("Не обнаружено данных для загрузки!");
	КонецЕсли;
	
	Возврат СписокГУИД;
	
КонецФункции

// Безопасно извлекает GUID из узла Заказ.GL.GUID
Функция ПолучитьГУИДЗаказа(Заказ)
	
	ГУИД = "";
	Попытка
		Если Заказ.GL <> Неопределено И Заказ.GL.GUID <> Неопределено Тогда
			ГУИД = СокрЛП(Заказ.GL.GUID);
		КонецЕсли;
	Исключение
		ГУИД = "";
	КонецПопытки;
	Возврат ГУИД;
	
КонецФункции
```

**Результат**

Сокращено время на обработку входящих заказов поставщиков. Исключены ошибки при ручном вводе данных. Автоматическое создание приходных ордеров по заказам из XML-файлов.

## Кейс 4. Заполнение документов из табличной части — интеграция ЕГАИС

**Задача**

При заполнении документов (заказы поставщикам, возвраты, установка акций, заявки на перемещение) из табличных частей файлов требовалось переносить специфические реквизиты ЕГАИС, которые не были предусмотрены в стандартном механизме заполнения.

**Что сделано**

В обработчике «Заполнение заказа из табличной части» добавлено заполнение реквизитов «Номенклатура ЕГАИС», «Справка Б» для документов, работающих с алкогольной продукцией. Для документа «Оформление возвратов» реализовано заполнение регистрационного номера (РН). Для «Установки акций для ТТ» добавлены реквизиты компенсаций поставщика и «Горилок», а также учетная цена.

```bsl
ЗаполнитьРеквизит("НоменклатураЕГАИС", нСтрока,СтрокаТовара.НоменклатураЕГАИС);
ЗаполнитьРеквизит("СправкаБ", нСтрока,СтрокаТовара.СправкаБ);
```

**Результат**

Полный перенос данных ЕГАИС при заполнении документов из внешних файлов. Ускорение процесса заполнения заказов и акций для алкогольной продукции. Исключение ручного вода реквизитов, критичных для интеграции с ЕГАИС.

## Кейс 5. Перемещение в торговый зал из ТТН ЕГАИС

**Задача**

При получении алкогольной продукции по входящим товарно-транспортным накладным ЕГАИС требовалось автоматически создавать документы перемещения товаров в торговый зал, при этом исключать дублирование и соблюдать правила статусной модели ЕГАИС.

**Что сделано**

Разработан механизм проверки статуса ТТН (должен быть проведен, груз принят, успешно обработан в ЕГАИС, входящий). Реализован контроль наличия уже созданного перемещения по данной ТТН с проверкой статуса отправки в ЕГАИС. Автоматическое заполнение табличной части перемещения из товарной части ТТН (номенклатура ЕГАИС, идентификатор строки, количество факт, справка Б). Сохранение документа для получения ссылки перед дальнейшей обработкой.

```bsl
Запрос = Новый Запрос();
Запрос.Текст = "ВЫБРАТЬ ПЕРВЫЕ 1
               |	ПеремещениеВТорговыйЗалЕГАИС.Ссылка,
               |	ПеремещениеВТорговыйЗалЕГАИС.СостояниеОбработкиЕГАИС
               |ИЗ
               |	Документ.ПеремещениеВТорговыйЗалЕГАИС КАК ПеремещениеВТорговыйЗалЕГАИС
               |ГДЕ
               |	(НЕ ПеремещениеВТорговыйЗалЕГАИС.ПометкаУдаления)
               |	И ПеремещениеВТорговыйЗалЕГАИС.Основание = &Основание
               |	И ПеремещениеВТорговыйЗалЕГАИС.Ссылка <> &Ссылка
               |
               |УПОРЯДОЧИТЬ ПО
               |	ПеремещениеВТорговыйЗалЕГАИС.Дата УБЫВ";
Запрос.УстановитьПараметр("Основание", ДокОснование);
Запрос.УстановитьПараметр("Ссылка", ЭтотОбъект.Ссылка);
Выборка = Запрос.Выполнить().Выбрать();
			
Если Выборка.Следующий() Тогда
	Если Выборка.СостояниеОбработкиЕГАИС = Перечисления.СостоянияОбработкиЕГАИС.ПустаяСсылка()
		ИЛИ Выборка.СостояниеОбработкиЕГАИС = Перечисления.СостоянияОбработкиЕГАИС.Ошибка Тогда					
		ДокПеремещения = Выборка.Ссылка;
		Возврат;					
	Иначе					
		Сообщить("Для ТТН уже создан документ перемещения в торговый зал и отправлен в ЕГАИС");
		Возврат;					
	КонецЕсли;				
КонецЕсли;
```

**Результат**

Автоматическое создание перемещений товаров из входящих ТТН без ручного ввода. Исключено дублирование документов. Товары в торговом зале учтены корректно и своевременно, что важно для розничной продажи алкогольной продукции.

## Кейс 6. Оприходование излишков из розницы — контроль движений

**Задача**

При оприходовании излишков товаров из розницы требовалось исключить формирование складских движений по регистрам, так как излишки уже учтены в розничных продажах и не должны влиять на складские остатки.

**Что сделано**

В документе «Оприходование товаров» добавлена проверка типа оприходования. Для типа «Излишки с розницы» движения по регистрам не формируются, при этом сам документ проводится и учитывается в системе.

```bsl
ИзлишкиСРозницы = ТипОприходованияИзлишков = Перечисления.ТипыОприходованияИзлишков.ИзлишкиСРозницы
```

**Результат**

Корректный учёт излишков товаров с розницы без искажения складских остатков. Соблюдение учетной политики и предотвращение завышения складских запасов.

## Кейс 7. Дисконтные карты — актуализация данных при загрузке

**Задача**

При загрузке дисконтных карт из внешних файлов в случае, когда карта с указанным кодом уже существует в системе, требовалось не просто выводить сообщение об ошибке, а актуализировать данные существующей карты.

**Что сделано**

Доработан алгоритм загрузки дисконтных карт: при обнаружении карты с существующим кодом выполняется её перезаполнение (ФИО, телефон, дата активизации, дата рождения) с последующей записью. Пользователь уведомляется о перезаполнении реквизитов.

```bsl
ОбъектДисконтнаяКарта	= ДисконтнаяКарта.ПолучитьОбъект();
						
Если ОбъектДисконтнаяКарта = Неопределено Тогда
	Сообщить("Дисконтная карта не найдена в базе. Запись не выполнена.");
	Возврат;
КонецЕсли;

ОбъектДисконтнаяКарта.КодКарты        = КодКарты;
ОбъектДисконтнаяКарта.Телефон         = Телефон;
ОбъектДисконтнаяКарта.ДатаАктивизации = Дата(СтрЗаменить(Лев(СтрЗаменить(ДатаРегистрации,"-",""),9),"""",""));
ОбъектДисконтнаяКарта.Возраст         = Дата(СтрЗаменить(Лев(СтрЗаменить(ДатаРождения,"-",""),9),"""",""));
ОбъектДисконтнаяКарта.ФИО             = СтрЗаменить(ФИО,"""","");
Попытка
	ОбъектДисконтнаяКарта.Записать();					
	Сообщить("Информационная карта с кодом "+КодКарты+" уже существует! Реквизиты перезаполнены.");
Исключение
```
